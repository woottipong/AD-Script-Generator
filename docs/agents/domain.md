# Domain docs

This repository uses a single domain context. Before exploring a domain, read the root [`GLOSSARY.md`](../../GLOSSARY.md) and any relevant decisions in [`docs/adr/`](../adr/).

- Use the glossary's canonical terms when naming domain concepts in code, issues, proposals, and tests. Note real vocabulary gaps for domain modeling rather than inventing synonyms.
- If a proposal contradicts an accepted ADR, name the ADR and explain why it should be reopened before proceeding.
