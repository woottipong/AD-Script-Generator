# 02: Confirm dialog แทน window.confirm

Status: resolved

Blocked by: 01

อ้างอิง: [spec](../spec.md) แถว "confirm"

**What to build:** ทุกคำถามยืนยันใน `App.tsx` (เปลี่ยนวิดีโอ, สแกนเสียงใหม่, สร้างบทใหม่, ออกจากหน้าตอนมีงานไม่ได้บันทึก ทั้งปุ่ม back และกลับรายการงาน, เริ่มงานใหม่) ขึ้นเป็น `AlertDialog` ของแอปแทนกล่องของเบราว์เซอร์ ข้อความเดิมทุกคำ และการกดยกเลิกต้องได้ผลเหมือนเดิม

- [x] `confirm({ title, description, confirmLabel, destructive })` คืน `Promise<boolean>` และเรนเดอร์ `AlertDialog` ตัวเดียวใน `App` ไม่มี `window.confirm` เหลือใน `src/`
- [x] ปุ่มยืนยันของการกระทำที่ทำให้ข้อมูลหาย (ออกโดยไม่บันทึก, สแกนใหม่, สร้างบทใหม่) ใช้ variant `destructive` ส่วนที่เหลือใช้ `default`
- [x] ปุ่ม back ที่ถูกปฏิเสธยังใส่ URL ของหน้าเดิมกลับเหมือนเดิม และ Escape หรือคลิกนอก dialog นับเป็นยกเลิก
- [x] focus เข้า dialog ตอนเปิด และกลับไปที่ปุ่มที่กดตอนปิด
- [x] browser tests ที่ stub `window.confirm` (`resume-cancel.js`, `job-lifecycle.js`) เปลี่ยนไปกดปุ่มใน dialog และตรวจทั้งกรณียืนยันและยกเลิก

## Comments

- การเบี่ยงจากใบ: คลิกนอก dialog ไม่ได้นับเป็นยกเลิก Base UI AlertDialog ตั้งใจไม่ปิดเมื่อคลิกนอก (ตามแนวทางของ alertdialog) เพื่อกันการกดพลาดตอนถามเรื่องงานจะหาย ยกเลิกได้ด้วยปุ่ม "ยกเลิก" หรือ Escape และ `resume-cancel.js` ตรวจว่าคลิกนอกแล้ว dialog ยังอยู่
- แก้เพิ่มที่เจอระหว่างทดสอบ: `jobSaveQueue.invalidate()` ล้างผลของ save ที่ค้างอยู่ ไม่อย่างนั้นการบันทึกที่ล้มเหลวของงานก่อนหน้าจะทำให้งานถัดไปขึ้นคำเตือนตอนออกทั้งที่ยังไม่ได้แก้อะไร มี unit test คลุมไว้
- แก้ตาม review: เก็บคำถามที่รออยู่ใน ref แทนการ resolve ข้างใน state updater
- ยังไม่ได้ทำ:
  - focus จะกลับไปที่ปุ่มในเมนู `จัดการ` ได้ก็ต่อเมื่อใบ 05 เปลี่ยนเมนูเป็น `DropdownMenu` เพราะตอนนี้ `<details>` ปิดตัวเองก่อนที่ dialog จะคืน focus
  - กด back ซ้อนสองครั้งระหว่างที่ dialog เปิดอยู่ จะเพิ่ม history ไปหนึ่ง entry กรณีนี้เกิดยากจึงยังไม่แก้
