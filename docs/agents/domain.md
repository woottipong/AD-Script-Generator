# Domain docs

This repository uses a single domain context. Before exploring a domain, read the root `GLOSSARY.md` and any relevant decisions in `docs/adr/`, if they exist. Proceed when they are absent; create them when domain terms or decisions are resolved, following the domain-modeling workflow.

Use the glossary's terms when naming domain concepts in issues, proposals, hypotheses, and tests. If a needed term is missing, check existing usage and note a real vocabulary gap for domain modeling.

If a proposal contradicts an ADR, identify the decision and explain why it may need to be reopened.
