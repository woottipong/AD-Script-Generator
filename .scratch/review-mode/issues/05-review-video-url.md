# 05: วิดีโอจาก URL ใน Review Mode

Status: resolved

Blocked by: 02

อ้างอิง: [spec](../spec.md) หัวข้อ "การเล่นวิดีโอและการสแกนเสียง (ไม่เปลืองพื้นที่)"

**What to build:** ผู้ใช้วาง URL ของวิดีโอ `.mp4` แทนการเลือกไฟล์ได้ วิดีโอเล่นและ seek จาก URL ตรงๆ การตรวจวิดีโอและการสแกนเสียงดึงข้อมูลเป็นช่วงด้วย HTTP Range โดยไม่เก็บไฟล์ลงดิสก์และไม่ส่งผ่าน server ของเรา รุ่นนี้ดึงทั้งไฟล์ผ่านเน็ตหนึ่งครั้งตอนสแกน

- [x] หน้ารับไฟล์ของ Review Mode รับได้ทั้ง URL ที่ลงท้าย `.mp4` และไฟล์บนเครื่อง
- [x] หาขนาดไฟล์จาก `Content-Length` ของคำขอ `HEAD` เพราะ `Content-Range` ไม่ได้ถูกเปิดให้อ่านข้าม origin
- [x] การตรวจวิดีโอและ worker สแกนเสียงอ่านข้อมูลผ่านช่องทางเดียวที่มีสองแบบแทนกันได้ คือไฟล์บนเครื่องกับ URL ที่ใช้ `fetch` + `Range` + `cache: 'no-store'` ดึงทีละก้อนแล้วทิ้ง
- [x] `<video>` เล่นจาก URL ตรงๆ และ Job บันทึก `video_source: { kind: 'url', url }` ตามที่ผู้ใช้วาง
- [x] ถ้าลิงก์ไม่รองรับ CORS หรือ Range ให้แสดงข้อความ "ลิงก์นี้เปิดจากเบราว์เซอร์ไม่ได้ กรุณาดาวน์โหลดแล้วเลือกเป็นไฟล์แทน"
- [x] มี unit test ของตัวอ่านแบบ URL (ขนาดจาก HEAD, การอ่านทีละช่วง, กรณีที่ไม่ได้ 206) โดยใช้ `fetch` ปลอม
- [x] ทดสอบด้วยมือกับ URL ตัวอย่างใน spec (1080p, 24:43) ว่าเปิด, seek, สแกน และส่งออกได้ และไม่มีไฟล์วิดีโอเพิ่มใน `.data/jobs`
